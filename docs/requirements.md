# 要件

## 目的

ディレクトリをたどりながら PDF・画像・動画を閲覧できる Web アプリを作る。シンプルさと保守運用のしやすさを重視する。将来は Android・iOS アプリ向けの API も担当する。

## 合意済みの要件

- ディレクトリ内のフォルダをフォルダとして表示し、移動できる。
- 一覧 API は指定ディレクトリ直下のフォルダと対象ファイルを全件返す。サブディレクトリ内は走査せず、ページ分割や検索は行わない。
- 対象拡張子は `.pdf`・`.gif`・`.webm`・`.png`・`.jpg`・`.jpeg` とし、大文字・小文字を区別しない。
- 一覧はフォルダを先に並べ、フォルダ同士・ファイル同士は名前の UTF-16 コード単位の昇順とする。
- シンボリックリンクと、通常のファイル・ディレクトリ以外の項目は一覧に含めない。
- 検索欄への入力に応じて、取得済みのフォルダ名・ファイル名をフロントエンドで部分一致により絞り込む。大文字・小文字と、ひらがな・全角カタカナを区別しない。例えば、`いうえ` で `あいうエオ` が一致する。半角カタカナは変換しない。
- 検索語を消すと取得済みの全項目を再表示する。ディレクトリ移動時は、ブラウザの戻る・進む操作も含めて検索欄をクリアする。
- 検索時に API リクエストは送信しない。検索対象は現在のディレクトリ直下の項目名のみとし、サブディレクトリ内の検索やファイル内容の全文検索は行わない。
- PDF をタイトルとサムネイルで表示する。
- PDF のサムネイルは、別のルートディレクトリに同じディレクトリ構造で存在する JPG を使用する。
- PDF は別タブで開く。
- GIF・WebM・PNG・JPEG は同じタブ内で拡大表示する。
- 拡大表示では左右ボタンのタップで前後のメディアに移動できる。
- サムネイルを Redis にキャッシュする。
- Basic 認証を利用できる。
- ディレクトリごとにスクロール位置を保存する。
- Next.js は使用しない。

## 現時点の想定

設計では以下を想定している。

- 「ローカルファイル」は、サーバーから参照できるディスクや NAS 上のファイルを指す。
- 初期段階は閲覧を中心とし、ファイルのアップロード・編集・削除は対象に含めない。
- ファイルシステムをコンテンツの正とし、初期段階でファイル一覧の DB は設けない。
