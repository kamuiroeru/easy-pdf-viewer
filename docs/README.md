# 設計ドキュメント

実装に先立って要件と設計を相談し、合意した内容をこのディレクトリに残します。

| ドキュメント                       | 内容                           |
| ---------------------------------- | ------------------------------ |
| [requirements.md](requirements.md) | 要件と前提                     |
| [architecture.md](architecture.md) | 採用する構成とコードの責務     |
| [decisions.md](decisions.md)       | 設計判断とその理由             |
| [research/](research/README.md)    | 技術比較、調査結果、検討中の案 |

## 更新方針

- 要件・設計の現在の状態は、それぞれのドキュメントに反映する。
- 採用理由や変更理由を残したい判断は `decisions.md` に日付付きで追記する。
- 提案や仮定は、合意済みの内容と区別して記載する。
- 調査メモは `research/` に置き、採用済みの要件・設計と区別する。
- 詳細な仕様が必要になったら個別のドキュメントを追加し、この一覧からリンクする。
- 要件・設計・判断理由・調査結果を記録する。
- 未決定事項、今後の対応課題、作業の進捗は記載しない。問題への対応は、利用者が問題を認識した時点で検討する。
