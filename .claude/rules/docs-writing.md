# ドキュメントの執筆

## 記載する内容

- `docs/` は、決定済みの仕様・方針・採用理由を記録する SSOT とする。プロダクトバックログとして使わない。
- 未決定事項、検討中の案、将来の拡張候補、TODO、仮定に基づく懸念は原則として記載しない。既存の記述を修正するときも、これらの情報は極力取り除く。
- 説明を広げるためだけの代替案や、採用していない機能・構成の提案を追加しない。採用理由を理解するために必要な比較は簡潔に残す。
- 個人プロダクトとして、問題が発覚してから修正対応を始める方針とする。仮想的な問題への予防策や対応計画を先回りして追加しない。
- 決定していない内容を推測で補ったり、決定済みの仕様として書いたりしない。依頼された記述に決定が必要なら、本文に「未定」「要検討」などを残す代わりに、会話で確認する。

## 日本語の推敲

- `docs/` 配下のドキュメントを追加・修正するときは、`yomiyasu:yomiyasu` スキルを使用して日本語の本文を推敲する。
- 使用前に、利用可能なスキル一覧から `yomiyasu` の `SKILL.md` を読み、その手順に従う。スキルの配置先は環境ごとに確認する。
- 推敲では、技術的な意味、仕様、条件、数値、識別子を保つ。
